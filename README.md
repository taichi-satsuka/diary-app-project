# aws

## 概要
AWS ECS(Elastic Container Service)を使用して、作成したアプリケーション作成したデプロイする

## 要素

## CIDR
- IPアドレスを可変長のネットワーク部分で表す方法
- どこまでがネットワーク部でどこまでがホスト部かを柔軟に書ける
- eg: 192.168.0.0/24<br>
    - このネットワークの範囲は 192.168.0.0 ~ 192.168.0.255
    - '/24' は前から**先頭から24bitはネットワーク部**を表している

```
特別なアドレス（予約済み）
1. 192.168.1.0: ネットワークアドレス（ネットワークそのものを表すアドレス）
2. 192.168.1.255: ブロードキャストアドレス（ネットワーク内の全端末宛への”全員集合！”アドレス）
```
private IP: インターネットに直接出られないアドレス<br>
global IP: インターネット上で唯一無二、外部から直接アクセスされる<br>


## VPC
- 自分専用のネットワーク（擬似的なLAN）
- プライベートアドレスしか使えない
    - 192.168.0.0/16
    - 172.16.0.0/12
    - 10.0.0.0/8
- この範囲をsubnetが分割して使う
    - VPC: 192.168.0.0/16<br>
    &rarr; public subnet1: 192.168.1.0/24<br>
    &rarr; public subnet2: 192.168.2.0/24<br>
    &rarr; private subnet1: 192.168.3.0/24<br>
- VPC CIDR &rarr; Subnet CIDR &rarr; ECSが使うENIが使うIP　という階層となる


## Subnet
- VPC内のIPアドレスをさらに分割した区画
- subnetで分割する理由
    1. 用途で隔離
        - eg.
            - publicサーバー（インターネットで公開したい）
            - privateサーバー（内部専用。RDS, ECSなど）
            - 管理系のサーバー
        - それぞれセキュリティを設定できるため管理がしやすくなる
    2. ルーティングを整理するため
        - どこから外に出る？のルールをサブネットごとに設定
            - インターネットに出るためにはIGW(Internet Gateway)が必要
            - プライベートサブネットはNAT GW経由で外に
    3. 可用性ゾーン（AZ）ごとに配置できる
- publicとprivateの違いはルートテーブルのみ
- 同一VPC内のsubnetは全て直接通信可能
- subnet間の通信をSG(Security Group), NACL(Network Access Control List)で制御する


## Route Table
- サブネットから出ていく通信の行き先を決める地図データのようなもの
- 「このこの宛先（destination）に送る場合はどの経路（target）を使うか」を定義
- 各サブネットにはひとつのルートテーブルが関連づけられる
- 複数のルートテーブルを作ることで、サブネットごとに異なる出口(igw/natなど)を設定可能

| 宛先（destination） | ターゲット（Target） |
|------------|--------|
| 10.0.1.0/24 | local |
| 0.0.0.0/0   | IGW   |
| 0.0.0.0/0   | NAT   |

local: 同じVPC内の通信<br>
0.0.0.0: インターネットアクセス用


## Security Group
- AWSにおける仮想ファイアウォール
- AWSの通信はデフォルトでは全て拒否
- 許可したものを通し、それ以外は暗黙で拒否
- statefulであるため、往復の片道だけ許可すればOK（両方設定する必要なし）
- インスタンスに紐づく
- インバウンド通信（外 &rarr; 中）とアウトバウンド通信（中 &rarr; 外）を分けて設定
    - 宛先port（ from_port / to_port ）
    - protocol（tcp, udp, -1 (全プロトコル) など）
    - source（インバウンド時） / destination（アウトバウンド時）（送信元（どこから）or 宛先（どこまで）の通信を許可するか）
        - CIDR_blocks(IP範囲) or security-groups(SG)を指定


## IAM
- AWS IAM は、AWS リソースに対する **認証（誰？）** と **認可（何ができる？）** を管理するサービス
- アカウントやロールごとにアクセス権限をきめ細かく設定できる

### 構成要素

#### 1. User（ユーザー）
- 個人またはアプリケーションを表す認証主体
- アクセスキー（CLI/SDK）、パスワード（コンソールログイン）を持つことができる

#### 2. Group（グループ）
- 複数のユーザーをまとめ、グループ単位でポリシーを付与できる
- 権限管理の効率化に利用

#### 3. Role（ロール）
- ユーザーではなく **AWSリソースに権限を付与** する仕組み
- 例：  
  - EC2 → S3アクセス  
  - ECS Task → CloudWatch Logs 出力  

#### 4. Policy（ポリシー）
- JSON形式で「何を許可/拒否するか」を書く権限ルール
- 例：`s3:GetObject`, `ec2:DescribeInstances`


## VPC endpoint
- VPC内のリソースが**インターネットを経由せずに**AWSサービスへアクセスできる仕組み
- セキュリティ強化、NATコスト削減につながる
- 2種類あり

#### 1. Gateway Endpoint
- 対応サービス：**S3 / DynamoDB**
- Route Table にルート追加して利用
- **無料**

#### 2. Interface Endpoint（PrivateLink）
- ENI（ネットワークインターフェース）を VPC 内に作成
- Secrets Manager / SSM / ECR / STS など多くのサービスで利用可能
- **有料**
- Security Group を設定できる

## ECS

AWS ECS（Elastic Container Service）は、AWSが提供するコンテナオーケストレーションサービスで、  
Dockerコンテナを簡単にデプロイ・管理・スケールするための仕組みを提供する。

### ECSの構成要素

### 1. Cluster（クラスター）
- ECSでタスク・サービスを動かすための論理的なグループ
- 実行基盤を「EC2」または「Fargate」から選べる

### 2. Task Definition（タスク定義）
- コンテナをどう動かすかを定義するテンプレート
- 含まれる設定例：
  - 使用するDockerイメージ
  - CPU / メモリ割り当て
  - ポート番号
  - 環境変数
  - ログ設定（awslogs など）

### 3. Task（タスク）
- タスク定義に基づいて **実行されているコンテナの集合**
- 1つのタスク＝1つ以上のコンテナ

### 4. Service（サービス）
- 指定したタスク数を常に維持する役割

### 5. Launch Type（起動タイプ）
- **EC2**: 自分でEC2インスタンスを用意してコンテナを動かす  
- **Fargate**: サーバレスでコンテナを動かせる（管理が楽）

### 6. タスクロールとタスク実行ロール

- ECS ではタスク定義に 2 種類の IAM ロールを設定

#### A. タスクロール（Task Role）
- タスク（＝コンテナ内のアプリケーション）が AWS リソースへアクセスするためのロール

#### 例：
- アプリが S3 にアクセスしたい  
- アプリが DynamoDB を読む/書く  

→ **アプリ（コンテナ）が AWS にアクセスする権限**

#### B. タスク実行ロール（Task Execution Role）
- ECS/Fargate がタスクを起動・管理する際に必要なロール。アプリではなく “ECS 実行基盤” が使う権限

#### 例：
- ECR から Docker イメージを pull  
- CloudWatch Logs にログを送信  
- Secrets Manager / SSM Parameter Store から環境変数を取得  
- ENI（ネットワークインターフェース）の作成（Fargate）

→ **ECS/Fargate がコンテナを準備＆起動するために使う権限**

#### 違いのまとめ（表）

| ロール名 | 使う主体 | 目的 |
|---------|-----------|-------|
| Task Role | コンテナ内アプリ | AWSリソースへアクセス |
| Task Execution Role | ECS/Fargateの実行基盤 | イメージpull、ログ出力、Secrets取得など |
